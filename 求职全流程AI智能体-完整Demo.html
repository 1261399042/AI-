一、项目简介与产品定位

1.1 产品名称

职途AI · 求职全流程智能体

1.2 目标用户

  • 应届毕业生（校招无全职经验）
  • 跨行业转行求职者
  • 0-3年职场跳槽人群

1.3 核心定位

区别市面单点简历/面试工具，一站式全链路AI智能体，覆盖求职完整闭环：职业诊断→简历优化→投递台账→笔试刷题→语音面试模拟→Offer对比谈薪→求职周期复盘；依靠Agent架构实现跨模块记忆互通，主动推送求职待办任务。

1.4 核心差异化壁垒

  • 功能壁垒：唯一完整覆盖求职7大核心链路AI产品
  • 数据壁垒：智能体全局记忆，无需重复填写个人信息
  • 体验壁垒：主动式任务提醒、自动求职复盘，竞品仅被动问答
  • 商业壁垒：三级分层付费（免费基础版/会员全功能/人工增值辅导）

三、用户调研与用户画像

本章以"需求-研究-聚类-画像-决策"的方法论闭环，为后续 KANO 需求分析提供用户侧依据。研究对象聚焦产品定位中的核心人群：应届毕业生、跨行转岗者与 0–3 年跳槽人群。

3.2 用户样本与数据采集

  • 定性样本：焦点小组 2 场（每场 8–12 人）+ 深度访谈 10 人（应届本科生 4 人、研究生 3 人、跨行转岗 2 人、1–3 年跳槽 1 人），覆盖 985/211/双非院校及互联网/快消/金融目标行业。
  • 定量样本：回收有效问卷 156 份，其中在校/应届求职者占比 78%，转岗/跳槽人群占比 22%。
  • 核心采集维度：求职阶段、已投递简历数、使用过的求职工具、最焦虑环节、每月愿意为求职工具付费的金额、15 项功能的需求强度（5 分制）。
  • 关键发现：67% 的受访者表示"不知道面试回答好不好"是最焦虑点；54% 愿意为"模拟面试 + 复盘"付费；仅 12% 认为"社群/排行榜"是必需的。

3.7 研究结论与产品设计启示

研究结论 证据 对产品设计的启示
1. 用户愿意为"确定性"付费 67% 受访者最焦虑"不知道回答好不好"；54% 愿为模拟面试+复盘付费 MVP 必须同时提供"练习"与"反馈"两个环节，缺一不可；复盘报告要给出可执行改进动作。
2. 效率型用户是早期付费主力 王刷题类用户占比 30%，付费意愿 49–79 元/月，且传播力强 优先满足"笔试组卷+错题本""JD 定向出题""一键导出"等效率型需求，作为首月付费转化抓手。
3. 进阶用户对"真实感"要求极高 张复盘类用户认为通用题太浅，需要多角色、语音、历史对比 文字模拟面试要加入追问、压力、多角色；语音版和历史追踪可作为 v1.5 高阶功能。
4. 社交/信息型需求当前优先级低 仅 12% 认为社群/排行榜必需；内推/日历打通在三类 persona 中均为低/中需求 R10/R13/R15 归入 P3 延后；R6/R7/R12/R14 作为 P2 兴奋型，在 MVP 后再探索。

5.9 竞品分析总结&复盘（核心结论）

  1. 市场格局结论：现有三类竞品分别只深耕简历、笔试题、通用问答单一场景，不存在覆盖求职全链路的AI智能体产品，赛道空白，差异化机会巨大。
  2. 三款竞品各自优缺点
    • 超级简历：优势=简历模板、JD匹配成熟；短板=链路残缺、数据割裂、无面试/投递闭环
    • 面试鸭：优势=笔试题库量大、错题基础功能完善；短板=仅面向刷题，无简历、Offer功能
    • ChatGPT：优势=灵活自由问答；短板=无求职专属架构、无法留存求职数据、操作成本高
  3. 我方三层差异化壁垒（匹配KANO优先级）
    • P0底层壁垒（必做）：全模块记忆互通，解决竞品重复录入信息核心痛点
    • P1核心付费壁垒（重点投入）：高Better值笔试题库、多版本简历、Offer多维对比，体验全面超越垂直竞品
    • P2独家亮点（增值付费）：AI主动任务提醒、每周自动复盘，三款竞品完全无同类功能
  4. 迭代落地策略
    • MVP阶段：优先落地4项P0基本需求（档案解析、台账、风险检测、数据互通），补齐竞品底层缺失能力
    • V1.0正式版：上线5项P1期望型功能，简历+笔试+面试体验全面对标并超越垂直竞品
    • V2.0增值版：上线2项P2兴奋型独家功能，打造竞品无法复制的付费核心竞争力

  • 价值完成率：收到面试题并完成模拟作答的用户 / 进入群的用户 ≥ 60%
  • 报告查看率：打开复盘报告的用户 / 完成模拟的用户 ≥ 70%
  • 付费意愿率：问卷中表示愿意付费的用户 ≥ 30%
  • 真实付费率：实际购买测试套餐的用户 / 活跃用户 ≥ 5%
  • NPS：净推荐值 ≥ 30（证明产品具备自然传播潜力）

8.3 一句话业务与商业模式

一句话业务：针对中文应届生及 0–3 年初级转岗者这一角色，在投递前准备、面试前突击、面试后复盘的场景下，通过"上传简历/JD → AI 定向出题 → 文字模拟面试 → 自动复盘报告"的任务闭环，帮助用户提升面试通过率与求职效率；商业模式采用"C 端订阅/按次付费 + B 端高校/培训机构/企业内推合作分成"双轮驱动。

要素 具体解释
角色 中文应届生（25/26 届）、0–3 年初级转岗者；核心为焦虑型校招小白、效率型刷题党、复盘型进阶者三类
场景 求职全链路中的三个关键焦虑点：① 投递前简历不知道好不好；② 面试前 1–3 天突击准备；③ 面试后不知道答得如何
任务 AI 简历诊断、JD 定向模拟面试、自动复盘报告、历史进步追踪，形成"诊断 → 练习 → 反馈 → 提升"的闭环
商业模式 C 端：Freemium（免费 3 场模拟）+ 会员订阅（29–79 元/月）+ 按次付费（9.9–19.9 元/场）+ 简历精修等增值服务；
B 端：高校就业中心 / 培训机构 / 企业内推渠道合作分成，按导流或成单计费

商业模式选择逻辑

之所以采用"C 端付费 + B 端合作"而非单纯广告或流量变现，原因有三：

  • 刚需 + 高焦虑：面试结果直接影响就业，用户付费意愿强，C 端订阅天然成立；
  • 低频但可前置：模拟面试本身是低频场景，但简历诊断、笔试组卷、JD 匹配是更高频的入口，能持续激活用户并为订阅转化蓄水；
  • B 端杠杆：应届生集中分布于高校与培训机构，B2B2C 可快速规模化获客，同时内推、校招信息等业务可带来额外变现。

战略层回答"为谁、解决什么、怎么赚钱"，是整个金字塔的顶点，也对应金字塔思维的"结论先行"。

战略要素本产品定义

9.3 结构层（Structure）—— 信息架构与核心链路

结构层定义"数据如何组织、模块如何串联"，是范围层功能背后的骨架。本产品的结构核心是跨模块记忆互通与全链路闭环：

职业诊断 → 简历优化（风险检测 / JD 匹配 / 多版本）→ 投递台账 → 笔试刷题（组卷+错题）→ AI 模拟面试（文字 / JD 定向 / 多角色）→ 自动复盘报告 → 多 Offer 对比谈薪 → 周期复盘　｜ 记忆互通贯穿全程，任意模块可调用历史上下文

结构上与单点工具（超级简历只做简历、面试鸭只做面试）的根本差异：以共享"求职档案 + 记忆"为中台，四个业务模块共享同一份用户上下文，越用越懂用户。

9.4 框架层（Framework）—— 交互框架与导航

框架构件设计要点

9.5 表现层（Presentation）—— 视觉与体验

表现层是用户最后感知到的"样子"，需服务战略目标（降低焦虑、提升信任）：

  • 低焦虑视觉：清爽蓝白主色、留白充足，弱化"考试感"，强化"陪练感"；
  • 报告可视化：结构化评分雷达 / 维度条 + 改进建议，让"好在哪、差在哪"一眼可读；

  • 轻量一致：卡片化组件、统一间距与圆角，保证四模块体验连贯。
